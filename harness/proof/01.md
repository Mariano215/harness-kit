# Proof 01: this repository's own three checks

This repository is not agentic: nothing in it calls a model, so by step 0 of
`TRANSFORM.md` every primitive is N/A and there is nothing to transform. What it
does have is three checks, and the rule in `contracts.yaml` at verification
level 4 applies to them: a check that has never been observed failing has not
been shown to be capable of failing.

## 1. The claim

`ci/contracts-well-formed.py`, `ci/adapters-cover-all-twelve.sh` and
`ci/consumers-cite-current-version.sh` each fail, name the offending file, and
name what is wrong with it.

## 2. The attack

Five deliberate breaks, each reverted immediately after:

1. Rename `## 08 Sub-agents` to `## 08 Delegation` in `adapters/agents/AGENTS.md`,
   removing the only mention of that primitive.
2. Bump `contracts_version` to `0.2.0` without touching any consumer citation.
3. Replace a `check:` value with malformed yaml: `check: ""forgot to write this`.
4. Replace a `check:` value with a whitespace-only string.
5. Add `definition:` to a contract entry, restating a field the spec owns.

## 4. What surprised you

Two things, and both were defects rather than confirmations.

The first run of NC3a produced a 30-line Python traceback ending in
`yaml.parser.ParserError` rather than a named failure. The check worked, in that
it exited non-zero, and it violated the rule it exists to enforce: the
verification contract says a sensor's failure message must name the fix, because
an agent reads that message and acts on it. A traceback names the parser's
internals. Fixed by catching `YAMLError`, reporting the line and column from
`problem_mark`, and naming the folded-block form as the likely repair.

The second is smaller and worth recording. The adapter check matches primitive
keys with `_` widened to `[ _-]`, because prose writes `sub_agents` as
"Sub-agents". That widening was written before NC1 ran, on the assumption it
would be needed. It was: without it the check would have passed the break in
step 1 for the wrong reason, matching nothing and reporting nothing, which is
the silent-green failure the negative control exists to catch.

## 5. Conformance delta

Not applicable. This repository makes no model call, so it is out of scope for
the rubric by the spec's own membership rule. Recording that here rather than
scoring it is the point: absence of a need is not maturity.

## 6. What is still a guide

Everything in `adapters/`. They are instruction fragments, and an instruction
fragment enforces nothing until the target project wires the sensors in step 4
of `TRANSFORM.md`. That is stated in the adapters themselves and in step 3, and
it is the single most important sentence in this repository.

The `cost` field on each contract is unverified judgment. It is drawn from having
implemented these controls, not from measurement, and no check can confirm it.
